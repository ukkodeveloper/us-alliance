# 1단계: 이해

목표: 사용자가 **30분 안에 과제와 코드를 자기 말로 설명할 수 있게** 만드는 것. AI는 분석·정리·시각화, 사용자는 해석·가정·범위 확정.

입력: `notes/assignment.md`, `notes/company.md`, `repo/`, progress.md(모드, 시안 유무).

## 1. 분석 (병렬)

주어진 레포 모드면 Explore 에이전트 2개를 한 메시지에서 띄운다:
- **구조**: 폴더 역할, 의존 방향, 라우팅, 상태·데이터 흐름, 공통 모듈(여러 곳에서 import되는 것), 기존 테스트 위치·명명
- **시나리오**: 핵심 사용자 흐름 1~2개를 클릭 → 핸들러 → 상태 → API → 렌더까지 file:line으로 추적 + 기존 코드 문제점(버그, 타입 구멍, 응집도·결합도)

그동안 메인은 요구사항을 분해하고, 시안이 있으면 화면 목록과 화면별 상태(정상·로딩·에러·빈)를 뽑는다 (Figma 도구가 있으면 사용, 이미지는 Read).

## 2. 보드 "이해" 섹션

`notes/board.html`의 "이해" 섹션을 만들어 Artifact로 publish한다. 처음 쓰기 전에 artifact-design skill을 로드하고, mermaid는 `<pre class="mermaid">`(라이브러리 불필요). 이후 같은 file_path로 재publish해 URL을 유지하고 progress.md에 기록한다.

| 섹션 | 내용 |
|---|---|
| 요약 | 무엇을, 누구를 위해, 핵심 흐름 3줄 |
| **중점 평가 기준** | G-n 원문과 해석. 요구사항 표와 별도로 맨 위에 둔다 |
| 요구사항 표 | `R-n` · 명시/암묵 · Must/Should/Nice(AI 제안) · 수용 기준 · **모호점 → 가정 후보(AI 추천)** · 엣지케이스 · 테스트 레벨(단위/통합/e2e/안 함) |
| 화면 (시안이 있을 때) | 화면 목록, 화면별 상태 |
| 코드 지도 (주어진 레포) | 구조 다이어그램, 시나리오 추적, 공통 모듈·수정 금지 목록, 요구사항 → 손댈 위치·영향 범위 |
| 기존 코드 문제점 (주어진 레포) | 문제 · 근거(file:line) · 과제 관련성 → 고칠지 / README 개선 제안만 할지 후보 |

처음부터 모드에서는 코드 지도 대신 "화면·데이터 흐름 초안"을 그린다.

## 3. 사용자와 확정 (Gate)

한 번에 하나의 주제로 짧게 묻는다.
1. 요구사항 해석과 Must/Should/Nice. **G와 직결되는 요구사항은 Must**, G 자체가 구현 항목이면(예: "테스트 작성", "반응형") 요구사항 표에 `R-n (G-k)`로 추가
2. 모호점별 가정 → 대부분 `N`, 구조에 영향을 주는 것만 `D` (`[요구사항]`)
3. 처리할 엣지케이스와 테스트 대상, 테스트하지 않을 것과 이유 → `N` (`[테스트]`)
4. 기존 코드 문제점: 고칠 것 / 제안만 → `N` 또는 `D` (`[기존코드]`)

확정 내용을 보드에 반영한다. 사용자가 승인하면 progress.md에 gate 시각을 기록하고 `/compact`를 권한다.

## 과하지 않게

- 요구사항에 없는 기능을 Must로 올리지 않는다. 차별화 아이디어는 Nice에 최대 2개, 사용자 관점 근거와 함께.
- 엣지케이스는 "발생 가능성 × 사용자 피해"가 큰 것 위주로 추린다.
