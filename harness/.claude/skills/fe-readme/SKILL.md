# 6단계: README

입력: `notes/{decisions,strategy,plan,company,progress,assignment}.md`, 보드 "이해" 확정 내용, `notes/qa/` 스크린샷, `references/templates/readme.md`, `references/ai-smell.md`.

## 0. 기존 README

주어진 레포의 README가 과제 설명이면 덮어쓰지 않는다. 사용자와 정한다: 원문을 `docs/ASSIGNMENT.md`로 옮김 / 하단에 내 섹션 추가 / 그대로 두고 새 문서.

## 1. 초안

`references/templates/readme.md` 구조. 섹션별 재료:

| 섹션 | 재료 |

| 실행 방법 | 0단계 기준선. **실제로 실행해 본 명령만** |

| 구현 범위 | R-n 체크리스트 + 가정 (N/D `[요구사항]`). 가정마다 그것을 고정한 **테스트 파일 링크** |

## 2. AI 활용 섹션

- AI 정책이 언급 없음이면 넣을지 사용자에게 묻는다.
- 구성:
  1. 역할 분담 표 (단계별 AI / 나) — decisions.md 출처 표기 기반
  2. 판단 사례 3~5개: AI 제안 → 내 판단 → 이유. **수정·거절(X) 사례와 함께 수용 사례도 1개** ("AI 추천을 이유 Y로 채택") — 거절만 고르면 연출로 보인다
  3. 검증 방식 1~2줄 (그룹별 QA, 새 맥락 리뷰·평가)
- 분량은 README의 1/5 이하. decisions.md에 없는 사례를 만들지 않는다.

## 3. 시각화

- mermaid는 GitHub에서 렌더된다. zip 제출이면 다이어그램 아래에 텍스트 설명을 두 줄 덧붙인다 (렌더 실패 대비).
- 스크린샷은 QA에서 남긴 정상·에러·빈 상태 중 의미 있는 것만 `docs/`로 복사.

## 4. 다듬기와 커밋

- `references/ai-smell.md` README 항목으로 점검 (이모지, 과장, 일반론, 템플릿 문구).
- 채팅에 섹션별로 보여주고 사용자가 문장을 고친다. AI는 사용자의 수정 방향(말투, 강조점)을 다른 섹션에도 맞춘다.
- README의 모든 주장이 코드·커밋에 있는지 확인한다.
- 승인 → `docs: README 작성` 커밋.
