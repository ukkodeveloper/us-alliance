# fe-tune — 파이프라인 튜닝

인자: `$ARGUMENTS`

대상은 **파이프라인 자체**다: `CLAUDE.md`, `.claude/skills/*`, `.claude/agents/*`, `.claude/hooks/*`, `.claude/settings.json`, `references/*`, `tools/*`.
과제의 `repo/`는 절대 건드리지 않는다. `notes/`는 아래 "진행 중 과제 맞추기"에서만 수정한다.

기록은 `tuning-log.md`(fe-task 루트, 없으면 만든다)에 남긴다.

## note — 기록만 (과제 흐름을 끊지 않음)

과제를 진행하는 중이면 기본은 note다. 5시간 안에서 파이프라인 수정에 시간을 쓰면 테스트 자체가 왜곡된다.

1. 지금 단계와 시각(`date "+%H:%M"`)을 progress.md에서 확인한다.
2. 아래 형식으로 한 항목을 추가하고, 다음 번호를 알려준 뒤 **즉시 원래 작업으로 돌아간다.**

```
### T-04 [open] 1단계 이해 · 예시과제 · 10:42
- 문제(사용자 원문): "기존 코드 문제점이 너무 많이 나와서 고를 수가 없음"
- 의심 위치: fe-understand §2 "기존 코드 문제점" 섹션
- 영향: 이해 단계 10분 초과
```

## fix — 바로 수정

인자가 `T-번호`면 그 항목을, 문장이면 새 항목을 만들어 처리한다.

1. **원인 찾기**: 어떤 파일의 어떤 지침이 이 동작을 만들었는지 찾는다. 지침이 없어서 생긴 문제인지, 지침이 틀렸는지, 지침끼리 충돌했는지 구분한다.
2. **수정안 제시**: 바꿀 파일과 전후를 짧게 보여준다. 원칙:
   - 새 규칙을 덧붙이기보다 **기존 문장을 고치거나 지운다.** 지침이 길어질수록 지켜지지 않는다.
   - 한 과제에서만 생긴 특수 상황이면 일반 규칙으로 만들지 말고 예외 한 줄로.
   - 시간 예산이나 단계 수를 늘리는 수정이면 그 비용을 함께 적는다.
3. **사용자 승인 후 적용.**
4. **일관성 점검**: 바꾼 이름·번호·경로가 다른 파일에서 쓰이는지 grep한다 (예: 단계 번호, `R-`/`D-`/`N-`/`X-`/`G-` ID, 파일 경로, 섹션 이름, code-style S·P 번호). 어긋난 곳을 함께 고친다.
5. **검증**: hook·lint 템플릿·스크립트를 바꿨으면 실제로 실행해 확인한다. 문서만 바꿨으면 해당 SKILL.md를 다시 읽어 지시가 모순 없이 읽히는지 확인한다.
6. **진행 중 과제 맞추기**: 바뀐 내용이 진행 중인 과제에 영향을 주면(템플릿 형식, progress.md 필드, 단계 순서) 그 과제의 `notes/`를 새 형식에 맞게 고치거나, 다음 단계부터 적용된다고 알린다.
7. tuning-log 항목을 `[fixed]`로 바꾸고 원인·수정 파일·검증 결과를 적는다.

```
### T-04 [fixed] …
- 원인: fe-understand §2가 문제점을 전부 나열하라고만 하고 개수 제한이 없음
- 수정: fe-understand.md — "과제 관련성 높은 순 최대 5개" 추가
- 검증: SKILL.md 재확인, 다른 파일 참조 없음
```

## review — 쌓인 노트 일괄 처리

과제가 끝났거나 단계 사이에 여유가 있을 때.

1. `[open]` 항목을 모아 **같은 원인끼리 묶는다.** 여러 노트가 한 지침에서 나온 경우가 많다.
2. 묶음마다 원인과 수정안을 표로 보여준다. 수정하지 않는 게 나은 것(이번 과제만의 특수 상황)은 `[wontfix]` 후보로 제시한다.
3. 사용자가 고른 것만 fix 절차 2~7로 처리한다.
4. 끝나면 `references/pipeline-guide.html`에 바뀐 내용이 반영되어야 하는지 확인하고, 필요하면 수정해 같은 file_path로 재publish한다.

## list

`tuning-log.md`의 `[open]` 항목을 번호·단계·한 줄 요약으로 보여준다.

## 반영 시점

- skill·agent·references·CLAUDE.md 수정은 같은 세션에 바로 반영된다.
- `settings.json`이나 hook 등록을 바꿨는데 동작하지 않으면 세션 재시작을 안내한다.
