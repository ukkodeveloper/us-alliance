# AI 냄새 체크리스트

AI가 만든 결과물에서 자주 보이고, 면접관이 "판단 없이 생성했다"고 읽는 신호들. 구현(fe-implementer), 리뷰(fe-reviewer), README(fe-readme)에서 사용한다.

## 코드

| 냄새 | 예 | 대신 |
|---|---|---|
| 쓰이지 않는 코드 | 호출처 없는 유틸, 미사용 export·props·타입, 미래 대비 옵션 | 삭제 |
| 성급한 추상화 | 사용처 1곳인 제네릭 컴포넌트·훅, 설정 객체로 모든 걸 받는 컴포넌트 | design-patterns P0 신호 확인 |
| 과잉 방어 | 타입상 불가능한 null 체크, 모든 함수의 try/catch, `?.` 남발 | 타입으로 보장, 경계에서 한 번 (P14) |
| 일반적인 이름 | `data`, `item`, `handleData`, `processInfo`, `utils.ts`, `helpers.ts`, `Manager` | 도메인 용어 (`orderSummary`, `handleQuantityChange`) |
| 스타일 흔들림 | 파일마다 다른 선언 방식·export·에러 처리 | code-style 일관 적용 |
| 기계적 메모이제이션 | 근거 없는 `useMemo`/`useCallback`/`memo` 도배 | 측정된 문제나 참조 안정성이 필요한 곳만 |
| 불필요한 상태 | props나 다른 상태에서 계산 가능한 값을 `useState` + `useEffect`로 동기화 | 렌더 중 계산 |
| 주석 | "// 사용자 데이터를 가져온다" 같은 설명 주석 | 이름으로 표현 (주석 금지) |
| 의미 없는 테스트 | 렌더링만 확인하는 스냅샷, 구현 상세(내부 state) 검증 | 수용 기준을 사용자 행동으로 검증 |
| 과한 타입 체조 | 필요 이상의 조건부·매핑 타입 | 읽히는 단순한 타입 |
| 라이브러리 과잉 | 작은 기능에 새 의존성 | 근거를 `decide`로 남기거나 직접 구현 |

## README

| 냄새 | 대신 |
|---|---|
| 이모지 헤더·장식, 과장된 형용사("강력한", "완벽한", "견고한") | 담백한 사실 |
| 일반론 ("유지보수성을 고려하여 설계했습니다") | 이 과제의 구체적 상황 → 선택 → 이유 |
| 모든 기술 스택 나열 + 일반적인 장점 설명 | 선택이 갈렸던 것만, 이 과제에서의 이유 |
| 코드에 없는 내용 | 실제로 구현·검증된 것만 |
| 길이 | 면접관이 5분 안에 핵심을 파악할 분량 |
| 결정 없이 "~를 사용했습니다"만 반복 | 포기한 대안과 재검토 조건 |
